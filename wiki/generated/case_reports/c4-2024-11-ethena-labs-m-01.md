## Summary

Blacklisted user can burn tokens during WHITELIST_ENABLED state. This breaks the main invariant from the README. This could become an issue when the admin tries to redistribute the blacklisted user’s UStb balance using redistributeLockedAmount() but the blacklisted user frontruns it with a burn.

## Broken invariants

- a blacklisted account must not be able to dispose of locked UStb by burning while blacklist enforcement is active
- whitelist mode must not override blacklist restrictions when an address accidentally or operationally holds both roles
- redistributeLockedAmount must not be front-runnable by the blacklisted holder through an allowed burn path
